PROBLEM WE ORIGINALLY HIT

Initial builds produced:

GLIBC_2.43 not found

Example:

./opencv_ncnn_test:
version `GLIBC_2.43' not found

Reason:

Compiler was finding libraries from WSL2 Ubuntu instead of Raspberry Pi.

Binary linked against:

glibc 2.43

Pi only had:

glibc 2.41

Result:

Binary compiled successfully.

Binary crashed on Raspberry Pi.

====================================================================
SOLUTION

Build against a Raspberry Pi sysroot.

Meaning:

Compiler sees Raspberry Pi files during build.

Not Ubuntu files.

Therefore:

Headers come from Pi.

Libraries come from Pi.

Linker uses Pi versions.

Generated binary becomes compatible with Pi.

STEP 8 - TOOLCHAIN FILE

File:

~/cross/arm64-rpi-toolchain.cmake

Purpose:

Force CMake to:

target ARM64
use sysroot
search Pi libraries
search Pi headers

.cmake file

arm64-rpi-toolchain.cmake

# ===== BASIC SYSTEM =====
set(CMAKE_SYSTEM_NAME Linux)
set(CMAKE_SYSTEM_PROCESSOR aarch64)

# ===== SYSROOT =====
set(CMAKE_SYSROOT $ENV{HOME}/sysroot/pi)

# Prevent host contamination
set(CMAKE_FIND_ROOT_PATH $ENV{HOME}/sysroot/pi)

set(CMAKE_FIND_ROOT_PATH_MODE_PROGRAM NEVER)
set(CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY)
set(CMAKE_FIND_ROOT_PATH_MODE_INCLUDE ONLY)
set(CMAKE_FIND_ROOT_PATH_MODE_PACKAGE ONLY)

# ===== COMPILER =====
set(CMAKE_C_COMPILER aarch64-linux-gnu-gcc)
set(CMAKE_CXX_COMPILER aarch64-linux-gnu-g++)

# ===== IMPORTANT FLAGS =====
set(CMAKE_C_FLAGS "--sysroot=${CMAKE_SYSROOT}")
set(CMAKE_CXX_FLAGS "--sysroot=${CMAKE_SYSROOT}")

set(CMAKE_EXE_LINKER_FLAGS "--sysroot=${CMAKE_SYSROOT}")
set(CMAKE_SHARED_LINKER_FLAGS "--sysroot=${CMAKE_SYSROOT}")

# ===== OPENCV + NCNN (CUSTOM /opt) =====
set(CMAKE_PREFIX_PATH
    ${CMAKE_SYSROOT}/opt/opencv
    ${CMAKE_SYSROOT}/opt/ncnn
)

# OpenCV hint (important for find_package)
set(OpenCV_DIR ${CMAKE_SYSROOT}/opt/opencv/lib/cmake/opencv4)

====================================================================
WHY GCC 15 ON WSL2 WORKS WITH GCC 14 ON PI

Compiler version and runtime version are different things.

Build machine:

GCC 15.2

Target machine:

GCC 14

This is fine.

What matters:

Binary linked against Pi libraries.

Because sysroot contains Pi glibc.

Therefore:

Compiler 15 generates code.

Linker uses Pi runtime.

Binary runs.
